# 実装構成

## モジュール

`LAMAudio2Expression` は Runtime。`LAMAudio2ExpressionEditor` は UncookedOnly で、AnimGraph 編集ノード、モデルのターゲット設定、接続例生成、PIE テストを持ちます。プラグインを導入するプロジェクトにエンジン改変は不要です。

| 実装 | 担当 |
|---|---|
| LAMAnalyzeAsync | BP通知、非同期モデルロード、解析ジョブ、PCM内容ハッシュ、LRU |
| LAMDecoder | Cook済みSoundWaveのUEデコーダーとストリーミングチャンクの保持 |
| LAMCore | リサンプル、窓切り出し、NNE推論、CPU代替、後処理 |
| LAMAudio2ExpressionComponent | AudioComponent、同期時計、再生制御、表情スナップショット |
| AnimNode_LAMARKit | GTでのスナップショット取得、AnyThreadでのカーブ合成 |
| LAMLive | マイク、PCM連続リサンプル、10フレーム単位推論、提示遅延 |
| LAMTypes | 上流固定順の52名、設定、Clip、Profile、補間 |

## スレッドと寿命

モデル UObject のロードと NNEモデル作成はゲームスレッドです。デコード、16kHzへの変換、NNEモデルインスタンス作成と推論、後処理は専用ワーカー1本で実行します。デコード中のチャンク待機もこのワーカー上です。実行中のNNE呼び出し自体は中断せず、キャンセルフラグで以後の処理と結果通知を止めます。

解析の共有データはUObjectを含まないジョブに保持します。完了のatomicフラグを確認してからゲームスレッドでClipへ移します。BPへの完了・進捗通知はゲームスレッドです。EndPlay、キャンセル、非同期アクション破棄でジョブを無効化します。

キャッシュの操作は専用ワーカーだけに限定します。キーは16kHz PCMのSHA-1、モデルのファイルGUID、スタイル、全後処理設定、処理版です。再生Clipは結果配列のコピーを所有し、キャッシュから独立して保持できます。64MiBはキャッシュ内のカーブ配列予算で、モデルと呼び出し側が保持するClipは別です。

AnimNodeのPreUpdateはカーブ配列とProfileをコピーします。Evaluate_AnyThreadはコピーとSourcePoseだけを使い、推論やUObject検索を行いません。カーブの式は `lerp(source, clamp(value * scale + offset, 0, 1), alpha * weight)`。無効カーブとボーン姿勢を変更しません。

## 時間

通常音声は16,000サンプルずつ進み、各34,133サンプル窓の出力64フレーム中34～63を採用します。開始前・終了後はゼロです。最終フレーム数は整数演算 `(samples * 30 + 15999) / 16000`。空の最終チャンクは作りません。

AudioComponentのネイティブ再生率コールバックから絶対音声時刻を取得し、次のコールバックまで最大1/30秒の補間予測を許可します。Seek時は新しいAudioComponentを作り、旧再生の通知を無視します。出力デバイス遅延の補償は含みません。

ライブは端数を保持して `hop * 16000 / 3` で窓終端を求めます。入力コールバックのキューは最大2秒、これとは別に推論用の過去文脈を保持します。推論が遅れると最新の完了ホップへ進みます。キャプチャのオーバーフロー時は残った最新音声へ時間基準を再設定し、世代番号で古い推論結果を破棄します。描画用結果は直近2秒です。

ライブの入力変換はゲームスレッドで行うため、Push PCM Audioに大きいチャンクをまとめて渡すより、音声コールバック相当の小さいチャンクを定期的に渡してください。ライブの自動瞬きはストリーム全体のフレーム位置と固定シードから決定します。

## モデル再現

`Tools/export_model.py` は固定リビジョンのネットワークをstrictで復元し、FP32/opset17/固定形状で出力します。学習・UI向け依存だけを切り離し、ネットワーク演算は変更しません。数値比較は後処理前のテンソルです。UEはNNEアセットに格納されたONNXとCook済みCPU/DirectML用データを使用します。
